# 前瞻与历史：自指选址的两条原则

## 一、这篇解决什么问题

在63号前瞻寻址的基础上，加入历史原则，验证"既要前瞻，又要历史"的自指选址原则。给出三种原则的对比实验与核心发现。

适合读者：对自指选址、前瞻搜索、历史聚合感兴趣的读者。

前提：27宫立方体，旧赋值，中宫为5。

## 二、两条原则

### 原则一：历史

用最近若干步的聚合值预测下一步，选择与预测一致的方向。

    函数 history_score(hist, pos, k):
        pred = mod9(sum(hist[-2:]))
        actual = mod9(V[pos] + k)
        返回 1 若 pred == actual，否则 0

### 原则二：前瞻

检查候选的下一步是否还有候选，优先选活路。

    函数 lookahead_ok(pos, nxt, k):
        nv = mod9(V[nxt] + k)
        返回 find_raw(nxt, nv) 或 find_bridge(nxt, nv) 是否非空

### 原则三：前瞻+历史

先看前瞻，再看历史，最后看方向惯性。

    key(p) = (死胡同标记, -历史一致, -方向惯性, 距离, 坐标)

|---|---|---:|

三种原则都不卡死，值恒为5。

## 四、实验二：预测一致性

随机选50个起点，每个走5步，比较三种原则的下一步选择是否一致。

| 原则 | 一致次数 |
|---|---:|
| history | 182/182 |
| lookahead | 182/182 |
| both | 182/182 |

**182次预测全部一致。**

关键发现：

> 前瞻和历史在绝大多数情况下指向同一选择，只在关键岔路处分化。

加3 z=1第4步就是关键岔路：

| 原则 | 第4步选择 | 结果 |
|---|---|---|
| history | (1,1,1) | 死胡同 |
| lookahead | (3,5,3) | 活路 |

## 六、核心发现

### 发现一：前瞻和历史通常一致

182次预测全部一致。两条原则不是对立，是互补。

### 发现二：关键岔路处分化

加3 z=1第4步，history选死胡同，lookahead选活路。这正是"既要前瞻，又要历史"的意义：历史给惯性，前瞻避死路。

### 发现三：前瞻优于纯历史

纯历史在加3 z=1卡死，前瞻不卡死。前瞻是防卡死的必要条件。

### 发现四：加1卡死需更深前瞻

加1值分布稀疏，前瞻深度1不够。可能需要深度2或更大半径。

### 发现五：自指回路周期保持

sum2周期24，与12号一致。历史原则不破坏自指结构。

## 七、结论

| 验证项 | 结果 |
|---|---|
| 加3 z=1 history | 卡死 |
| 加3 z=1 lookahead | 不卡死 |
| 加3 z=1 both | 不卡死 |
| 加1 z=1 三种 | 均卡死 |
| 加9 三种 | 均不卡死 |
| 预测一致性 | 182/182 |
| sum2周期 | 24，与12号一致 |

## 八、自指选址原则

> **既要前瞻，又要历史。历史给惯性，前瞻避死路。两者通常一致，关键岔路处分化。**

在实现上：

1. 前瞻优先：排除死胡同候选；
2. 历史辅助：在活路中选与历史一致的方向；
3. 方向惯性兜底：历史无信号时用惯性。
