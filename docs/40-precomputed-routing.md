# Polaris 基础架构：基于静态查表（LUT）的零开销预计算路由

## 一、本文解决什么问题

在传统的大模型（如 MoE 架构）中，每次前向传播时的“专家路由（Expert Routing）”，都需要实时进行庞大的浮点矩阵乘法，这在边缘计算或高并发场景下带来了严重的延迟。
既然 Polaris 引擎的状态空间被严格限制在纯整数域（如模10的 0~9），系统的可能状态组合是**有限且可穷举的**。本文提出一种**“预计算路由（Precomputed Routing）”**机制，将所有的状态转移与路由决策，在离线阶段全部固化为静态查找表（Look-up Table, LUT）。在推理阶段，系统以 \(O(1)\) 的时间复杂度直接查表，实现了零浮点开销、零延迟的路由计算。

## 二、核心机制：状态穷举与查表路由

### 1. 状态空间穷举
假设系统的输入特征被降维至 0~9，当前节点的历史状态也被限制在 0~9。这两个变量组合出的可能情况，仅有 \(10 \times 10 = 100\) 种。
对于这 100 种确定的输入，其经过拓扑偏移、双墙约束或状态机重置后的结果，也是唯一确定的。

### 2. 路由表固化（Routing Table）
我们将这 100 种映射关系预计算，生成一个二维矩阵（或一维数组）。
- **行索引**：代表当前节点的状态值（0~9）。
- **列索引**：代表输入的新特征值（0~9）。
- **矩阵元素**：代表计算好的下一跳路由目标（或更新后的新状态）。

### 3. 硬件级查表（Hardware LUT）
在 FPGA 或神经拟态芯片中，这种二维数组可以直接映射为硬件内部的 LUT（查找表）或 ROM（只读存储器）。当输入到达时，不需要任何 ALU（算术逻辑单元）参与运算，通过硬件 MUX（多路选择器），即可在 1 个时钟周期内输出路由结果。

## 三、工程价值

1. **彻底剥离浮点运算**：无论多复杂的路由拓扑，只要穷举完毕，运行时就全部变成了“查表”。
2. **极致的高并发**：查表操作没有数据依赖，多线程或并发请求可以同时读取同一张静态表，不需要任何锁机制。
3. **确定性延迟**：因为去掉了复杂的计算过程，系统的延迟恒定不变（1 tick），这对于自动驾驶、机器人控制等要求硬实时（Hard Real-time）的场景至关重要。

## 四、代码实现

    def build_routing_lut():
        """
        离线预计算：构建 10x10 的路由查找表 (LUT)。
        规则模拟：(当前状态 * 3 + 输入特征 * 7 + 空间偏置5) % 10
        """
        lut = [[0] * 10 for _ in range(10)]
        for state in range(10):
            for feature in range(10):
                # 预计算路由结果
                lut[state][feature] = (state * 3 + feature * 7 + 5) % 10
        return lut

    class PrecomputedRouter:
        def __init__(self):
            # 在系统启动时加载离线计算好的表
            self.lut = build_routing_lut()

        def route(self, current_state, input_feature):
            """
            在线推理：零计算，纯查表。
            """
            # 直接通过数组索引获取结果，时间复杂度 O(1)
            return self.lut[current_state][input_feature]

    if __name__ == "__main__":
        router = PrecomputedRouter()
        
        # 模拟实时推理请求
        test_cases = [(3, 7), (0, 0), (9, 9), (5, 2)]
        print("=== 零开销查表路由测试 ===")
        for state, feature in test_cases:
            target = router.route(state, feature)
            print(f"当前状态: {state} | 输入特征: {feature} -> 路由目标: {target}")

## 五、结论

| 验证项 | 结果 |
|---|---|
| 空间穷举 | 10x10 的状态空间被完全预计算固化为 LUT |
| 查表路由 | 运行时无需任何算术运算，直接索引查询 |
| 实时性 | 延迟降至硬件极值，极度适合硬实时系统 |
