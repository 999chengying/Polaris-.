# 事件驱动与定时轮询：阴阳辩证与混合策略

## 一、实验背景

在动态目标模型中，目标每隔若干步随机移动一次。
对比两种通信策略：

- 事件驱动（event）：目标变化时才通信；
- 定时轮询（poll）：每隔固定步数查询一次。

## 二、实验数据

### 目标每20步移动

| 策略 | 步数 | 通信次数 | 成功率 |
|---|---:|---:|---:|
| event | 213.8 | 1.8 | 20/20 |
| poll_20 | 213.8 | 3.0 | 20/20 |
| poll_50 | 211.0 | 1.0 | 3/20 |

通信成本低时 event 最优，通信成本高时 event 仍优。

### 目标每10步移动

| 策略 | 步数 | 通信次数 | 成功率 |
|---|---:|---:|---:|
| event | 213.1 | 3.4 | 20/20 |
| poll_20 | 213.5 | 3.0 | 20/20 |
| poll_10 | 213.1 | 5.0 | 20/20 |

通信成本低时 event 优，通信成本高时 poll_20 优。

### 目标每5步移动

| 策略 | 步数 | 通信次数 | 成功率 |
|---|---:|---:|---:|
| event | 213.8 | 6.7 | 20/20 |
| poll_20 | 213.1 | 3.0 | 20/20 |
| poll_5 | 213.8 | 9.0 | 20/20 |

通信成本无论高低，poll_20 均优。

## 三、核心规律

目标变化越快，event 通信次数增长越快。

poll 通信次数固定，不随目标变化波动。

| 目标移动间隔 | event通信 | poll_20通信 | 最优策略 |
|---:|---:|---:|---|
| 20步 | 1.8 | 3.0 | event |
| 10步 | 3.4 | 3.0 | 成本低event，成本高poll |
| 5步 | 6.7 | 3.0 | poll |

结论：

目标变化慢时，事件驱动优。
目标变化快时，定时轮询优。
最优策略是混合：事件驱动 + 周期兜底。

## 四、阴阳辩证

事件驱动为阳：

- 主动；
- 敏感；
- 随目标变化；
- 快，但易亢。

定时轮询为阴：

- 被动；
- 稳定；
- 固定周期；
- 慢，但可预测。

纯阳则事件风暴：

- 目标变化越快，通信次数越多；
- 系统被通信淹没；
- 光模块需求暴涨。

纯阴则反应迟钝：

- 目标变了，系统还不知道；
- 错过更新；
- 成功率下降。

阴阳相济：

- 事件驱动为主，捕捉变化；
- 周期轮询为辅，兜底限流；
- 通信次数有上界，系统稳定。

## 五、工程含义

纯事件驱动会被事件风暴淹没，需要轮询兜底。

操作系统：事件驱动 + 定时器兜底。
网络协议：事件 + keepalive轮询。
监控系统：事件 + 定期心跳。
分布式系统：事件 + 周期同步。

通信需求有上界：

通信需求 ∝ min(目标变化频率, 轮询频率上界)

目标变化极快时，系统会切换到轮询模式，通信次数被限流。
光模块需求不会随目标变化频率无限增长。

## 六、对AI架构的启示

AI推理目标变化快，但不能纯事件驱动。

推荐混合架构：

- 事件驱动：目标变化时立即通信；
- 周期轮询：固定间隔兜底；
- 自适应轮询：根据目标变化频率动态调整轮询间隔。

目标变化慢：拉长轮询间隔，靠事件。
目标变化快：缩短轮询间隔，限流事件。

## 七、固化条目

目标变化慢：事件驱动优。
目标变化快：定时轮询优。
最优策略：混合，事件驱动 + 周期兜底。
通信需求有上界，光模块需求不会无限增长。

## 八、口诀

事件为阳轮询阴，纯阳则亢纯阴滞。
阴阳相济方为道，混合策略最相宜。
目标慢时事件优，目标快时轮询稳。
通信需求有上界，光模块涨也有顶。
