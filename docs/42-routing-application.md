# 应用验证：9节点消息路由系统

## 一、这篇解决什么问题

在一个9节点网络中，对比三种路由方法：

- 实时BFS：每次查询搜索；
- 预置路由表：预存所有路径；
- 九宫引擎：利用链结构，链优先、合十次之、BFS兜底。

目的是验证：九宫引擎在真实任务中的表现。

适合读者：对路由、缓存、结构导航感兴趣的读者。

## 二、网络拓扑

9个节点，邻接关系从39号的链结构推导：

- 阳链：1-2-4-7；
- 阴链：9-8-6-3；
- 258链：5-8；
- 合十对：1-9、2-8、3-7、4-6。

拓扑无向，每个节点连接若干邻居。

## 三、三种方法

| 方法 | 策略 | 预计算 |
|---|---|---|
| BFS | 每次搜索最短路径 | 无 |
| 查表 | 预存81对路径 | 全部 |
| 引擎 | 链优先，合十次之，BFS兜底 | 链表 |

## 四、实验结果

### 1. 正确性

九宫引擎在所有72对非对角路由中，失败0对。

### 2. 路由长度

| 起点到终点 | BFS | 查表 | 引擎 |
|---|---:|---:|---:|
| 1到5 | 3 | 3 | 3 |
| 1到9 | 1 | 1 | 5 |
| 3到5 | 3 | 3 | 3 |
| 4到7 | 1 | 1 | 1 |
| 6到8 | 1 | 1 | 3 |
| 7到5 | 4 | 4 | 4 |

引擎在部分路径上不是最短，因为链优先策略可能绕路。

### 3. 批量性能

10000次随机路由：

| 方法 | 时间 | 每次 |
|---|---:|---:|
| BFS | 0.0376秒 | 3.76微秒 |
| 查表 | 0.0018秒 | 0.18微秒 |
| 引擎 | 0.0195秒 | 1.95微秒 |

### 4. 内存

| 方法 | 存储量 |
|---|---:|
| BFS | 0项 |
| 查表 | 243项 |
| 引擎 | 18项 |

### 5. 可解释性

| 方法 | 可解释性 |
|---|---|
| BFS | 仅路径 |
| 查表 | 仅路径 |
| 引擎 | 路径加链结构 |

## 五、核心结论

三种方法都能正确路由。

查表最快，但内存最大。

引擎折中：内存小，速度介于两者之间。

引擎可解释性最好。

引擎在部分路径上不是最短，这是链优先策略的代价。

## 六、适用场景

| 场景 | 推荐方法 |
|---|---|
| 内存充足，追求速度 | 查表 |
| 内存受限，需可解释 | 引擎 |
| 无预计算需求 | BFS |
| 动态拓扑 | BFS |
| 静态拓扑、长期服务 | 查表或引擎 |

## 七、边界声明

本实验只针对9节点网络。

结论不能直接外推到大型网络。

引擎的最短性不是保证的，链优先可能绕路。

可定义、可推导、可检验；有用则留，无用则弃。

## 八、口诀

九节点上路由明，三种方法各不同。
查表最快内存大，BFS无存搜得清。
引擎折中链结构，可解释性好又省内存。
不是最短是代价，场景选择要分清。
